# RE:PAIR
## 동적 스마트팩토리 환경에서의 자율주행 로봇팔 AGV 기반 설비 고장 진단 및 자동 보수 시스템

> 스마트팩토리 설비의 이상을 통신으로 인지하고, 동적 공장 환경에서 고장 설비까지 자율주행하여 로봇팔로 맞춤형 보수 작업을 수행하고 정상 복구까지 검증하는 이동형 자동 유지보수 시스템.

**현재 단계: 사전 조사·기획.** 아래 시나리오와 기술 구성은 개발 방향을 설명하는 초안이며, 구현 완료나 성능을 의미하지 않습니다. 세부 기능·장비·통신 방식·중앙 작업 관리자 도입 여부·보수 유형은 검증 후 확정합니다.

## 배경과 목표

설비 이상 대응에는 현장 이동, 원인 확인, 보수, 재가동 확인이 필요합니다. 이 과정을 이동 로봇과 로봇팔로 연결하는 가능성을 모형 환경에서 검증합니다. 실제 산업현장에서 필요한 상황과 기존 방식 대비 효용성은 사전 조사 대상입니다.

실제 산업용 설비 대신 고장 상황을 재현할 수 있는 소형 생산설비를 직접 설계·제작하는 방향을 검토합니다. 로봇팔이 처리할 수 있도록 정의한 고장·작업 범위를 대상으로 하며, 범용 산업 설비 수리나 산업 안전 인증 확보를 주장하지 않습니다.

## 핵심 기능 — 구현 목표

| 기능 | 검토 중인 구현 방향 |
|---|---|
| 고장 인지 및 작업 연계 | 이상 상태·오류 정보를 수신하고 고장 유형에 맞는 보수 작업 연결 |
| 동적 환경 자율주행 | 작업자·장애물·폐쇄 구역 대응, 안전 정지 및 필요시 경로 재계획 |
| 정밀 도킹 및 위치 보정 | 설비 앞 위치·방향 오차를 줄여 로봇팔 작업 위치 정렬 |
| 고장 유형별 로봇팔 자동 보수 | 이물질 제거·부품 재정렬·모듈 교체 등의 실현 가능성 검증 |
| 자동 복구 검증 | 보수 동작 완료와 실제 설비 정상 복구를 구분하여 판정 |

센서 퓨전, 통신 실패·중복 작업 방지, 안전 인터록, 주행·로봇팔 실패 처리, 관제 UI, QA 중심 검증을 공통 검토합니다.

## 예상 동작 시나리오

1. 모형 생산설비에서 이상을 감지하고 고장 상태·오류 정보를 생성합니다.
2. 통신으로 고장 요청을 전달하고 작업 가능 상태와 보수 유형을 확인합니다.
3. AGV가 고장 설비로 이동하며 변화하는 통행 환경에 대응합니다.
4. 설비 앞에서 정밀 도킹하고 위치·방향을 보정합니다.
5. 설비 안전 정지와 작업 조건을 확인한 뒤 로봇팔로 보수합니다.
6. 설비 시험 동작으로 정상 복구 여부를 확인합니다.
7. 성공·실패 결과와 이력을 기록하고 AGV가 복귀합니다.

중앙 관리자를 사용하는 흐름은 후보 구조입니다. 실패 시 정지·보고·조건부 재시도 방법과 구체적 완료 기준은 조사·실험 후 정합니다.

## 시스템 구성 후보

| 구성 | 후보 장비·역할 | 상태 |
|---|---|---|
| 생산설비 | STM32/ESP32 기반 소형 모형 설비 | 검토 중 |
| 이동 로봇 | Jetson Nano 기반 로봇팔 장착 AGV | 보유 장비·호환성 확인 필요 |
| 중앙 작업 관리자 | 고장 정보 수집·작업 할당·상태 관리 | 도입 여부 검토 중 |
| 관제 UI | 설비 상태·AGV 위치·작업 진행·결과 표시 | 범위 검토 중 |

주행 센서, 도킹 방식, 통신 프로토콜, 언어·프레임워크, 로봇팔 작업 범위는 미정입니다. 저전압 모형 설비에서도 물리적 비상정지·전원 차단과 안전한 시험 환경을 확보하고, 소프트웨어 인터록만으로 이를 대신하지 않습니다.

## 협업 원칙

- 최신 `main`에서 작업별 브랜치를 만들고 PR로 병합합니다. 개인별 고정 브랜치는 사용하지 않습니다.
- 평소 상대방 리뷰를 받은 뒤 병합합니다. 긴급한 경우 PR에 사유·테스트·영향·복구 방법을 남기고 본인이 병합한 뒤 사후 리뷰를 요청합니다.
- 커밋: `type(scope): 변경 내용`. 예: `feat(docking): 마커 기준 위치 오차 계산 추가`.
- PR에는 **한 일 / 실행·테스트 방법 / 기대·실제 결과 / 미검증·문제점 / 다음 작업 / 리뷰 요청**을 작성합니다.
- 미완성 작업은 Draft PR로 공유합니다. 미검증 내용을 성공으로 기록하지 않습니다.

## 시작하기

```bash
git clone https://github.com/psy1218/repair-agv-robotarm-maintenance.git
cd repair-agv-robotarm-maintenance
git switch main
git pull --ff-only origin main
git switch -c feat/<실제-Jira-키>-<작업명>
```

꺾쇠 괄호는 실제 값으로 바꿉니다. 예시 키 `RE-12`를 사용한다면 `feat/RE-12-docking-offset` 형태입니다.

아직 실행 가능한 애플리케이션·펌웨어·자동 테스트는 없습니다. 기술 구성 확정 후 [개발 환경 문서](docs/DEVELOPMENT.md)에 실제 설치·빌드·실행 명령을 추가합니다.
